## Session 01:03–01:25 UTC — UGC Style Fix (Prompt/Router Agent/Recipe overhaul)

### Problem
- User reported: selecting "Holding product UGC" still generates demonstration/usage videos
- Product packaging shown incorrectly (twist cap → pump bottle, wrong cap style)
- Product barely visible in frame ("แทบไม่มีสินค้าคู่นางแบบเลย")

### Root Causes (4 layers)

1. **Router Agent overriding user style** (MAIN BUG):
   - `analyze_and_build_prompts()` in `prompt_builder.py` had logic: if `ugc_style == "holding"` and Router Agent says != "holding" → override
   - Router Agent always suggests "visual_style" based on product analysis → user's "holding" choice was always ignored
   - **Fix**: Removed the override. Router Agent is now purely advisory.

2. **Packaging action inference wrong for holding**:
   - `build_video_prompt()` in `prompt_builder.py` always inferred packaging actions (pump/spray/blend/dab/etc.) based on product name keywords
   - For "holding" style, no packaging action should be inferred — just "hold and show"
   - **Fix**: Added early check: if `ugc_style == "holding"`, skip all packaging inference, use `generic_hold` directly

3. **Video prompts had no "NOT using" instructions**:
   - Wan 2.7 invents random usage motions even when prompt says "holding"
   - **Fix**: Added explicit negative instructions: "Do NOT open or apply the product. No squeezing, no pumping, no spraying."

4. **`analyze_product()` in pipeline_affiliate.py hardcoded ugc_style**:
   - Line 133: `"ugc_style": "holding"` was hardcoded regardless of caller
   - **Fix**: Added `ugc_style` parameter to `analyze_product()` and passed it through

5. **`build_video_prompts()` in pipeline_affiliate.py ignored ugc_style**:
   - Generated scene-specific demo prompts for ALL 6 TUS recipe scenes
   - **Fix**: Added `ugc_style` parameter. For "holding" style, ALL scenes now use generic hold prompt instead of usage descriptions.

6. **STYLE_MAP in prompt_templates.py too weak**:
   - "holding" model_action said "holding product" without "NOT applying/using"
   - **Fix**: Added "NOT applying or using product, NOT opening product, just holding and showing"

### Files changed
- `prompt-builder-service/prompt_builder.py` — Router Agent override removed, packaging action skip for holding, negative emphasis in video prompt, negative emphasis in image prompt, `generic_hold` motion hardened
- `prompt-builder-service/prompt_templates.py` — STYLE_MAP "holding" action + camera + keywords strengthened
- `modules/video/pipeline_affiliate.py` — `analyze_product()` + `build_video_prompts()` now accept and pass `ugc_style`

### Commit
- `9dae177` — "fix: UGC style enforcement + prompt improvements for holding style"

## Session 01:25–02:55 UTC — Product Physical Details + Gemini Analysis Overhaul

### Problem
- User reported: product barely visible in frame, wrong cap (pump vs twist), wrong usage actions
- After fixing Router Agent override and model_cast positions, user asked: **"รายละเอียดสินค้าควรใส่แค่ไหน"** (how detailed should we describe the product?)

### Root Cause Analysis
- Image prompt used `model_cast.get("image_description")` EXCLUSIVELY — cast's generic descriptions had NO product-specific packaging details
- Video prompt had NO product physical description at all — Wan 2.7 had to guess bottle shape, cap type, label
- Gemini's `analyze_product()` output excellent `image_description` (e.g. "clear plastic bottle with green label and white twist cap") BUT this was NEVER used in the final prompt — only model_cast won

### User's Key Insight
- Don't stuff raw product specs into Wan 2.7 (it'll get confused)
- **Feed detailed product info (cap type, texture, usage) to Gemini** → Gemini writes natural-language prompts
- The product analysis (Gemini vision) already sees the product image — just needs a better system prompt to output packaging details

### Fix Implemented
1. **`gemini_client.py` — SYSTEM PROMPTS updated**:
   - `PRODUCT_ANALYSIS_SYSTEM`: Added requirement to describe container type (bottle/jar/tube), closure (twist cap/pump/spray/flip-top), product color/texture, label/design
   - `PRODUCT_VISION_SYSTEM`: Same — Mandate product physical packaging details in `image_description`

2. **`prompt_builder.py` — Merge model_cast + Gemini**:
   - `build_image_prompt()`: After selecting model_cast (for varied appearance), now EXTRACTS product packaging sentences from Gemini's `image_description` and appends them
   - `build_video_prompt()`: Now includes `"showing a [product physical description]"` at start of video prompt

3. **Resulting prompts now include**:
   - Image: "...holding product at chest level. **The product is a clear plastic bottle of Naturista Tea Tree Facial Toner with a green and white label and a black twist cap.**"
   - Video: "Thai woman 22 **showing a clear plastic bottle of Naturista Tea Tree Facial Toner with a green and white label and a black twist cap**. Model gently holding..."

### Key Principle
- Model cast = model appearance variety (age, skin, clothes, style)
- Gemini analysis = product packaging details (container, cap, color, label)
- They now MERGE instead of one winning over the other

## Session 03:00–08:39 UTC — Vision Provider Swap + Packaging Extraction + Full Pipeline Fix

### Problems Fixed
1. **Gemini Vision has 6-rpm rate limit** — too slow for production, fails under load
2. **Mistral Vision rejects product image URLs** from Unsplash/Cloudflare CDNs — returns "invalid URL" error
3. **Packaging extraction from image_description captured model appearance** — sentences like "An ethnic Thai woman... applying the lip product" contained "product" so got included
4. **Nano Banana img2img rejects `negative_prompt`** in config — 400 error with job reference object
5. **Prodia sync API sometimes returns job reference instead of image bytes** — needs polling
6. **`build_video_prompts()` creates hardcoded `hold_base`** ignoring `_video_prompt` from prompt-builder-service — root cause of video prompt not reflecting image prompt changes
7. **No recipe existed in Schema Engine** — "video_recipe" schema was empty, `load_recipe()` returned 0 scenes, fallback to generic "Product showcase, smooth motion"
8. **Age always 25** — hardcoded in both image and video prompts

### Fixes Applied
1. **Mistral Vision (Pixtral) replaces Gemini Vision**:
   - Added `_call_mistral_vision()` in `gemini_client.py` with base64 data URI (downloads image locally, converts to base64, sends to Mistral)
   - Mistral backend can't fetch URLs from some CDNs — base64 bypasses this
   - Gemini Vision kept as fallback

2. **Packaging sentence extraction bug fixed**:
   - Skip sentences whose first 40 chars contain "thai woman", "thai man", "model", "ethnic thai"
   - Require sentences to start with "the product", "the packaging" OR contain container words (bottle, tube, click, mechanism, cap, etc.)
   - Strip redundant prefixes like "The product is" / "The packaging is"

3. **Sanitize scene_desc aggressively for holding style**:
   - Replace usage verbs: `applying → holding`, `apply → hold`, `uses → holds`, `using → holding`
   - Remove `squeez`, `pump`, `spray`, `open` references
   - Replace `near/her lips` → `at chest level`
   - Replace `demonstrat/showcas...ease of use/application` → `presenting the product`
   - Replace `enhanc(e|ing) the lips` → `showing the`
   - **CRITICAL: Sanitize BEFORE prompt construction** — Flux/Nano Banana ignore "NOT applying" if "applying" appears in prompt
   - Final pass: strip remaining `her lips`, `his lips`, `on her/his lips/skin/face`, `glossy...lips`

4. **Prodia v2 sync API fix**:
   - `negative_prompt` removed from config dict entirely (API rejects it)
   - Added polling logic: when Prodia returns job reference JSON with `id`, poll `/v2/job/{id}/result` up to 30 times (2s interval)
   - Thai face filtering done via prompt text modification, not negative_prompt

5. **`build_video_prompts()` now uses `_video_prompt`**:
   - Replaced hardcoded `hold_base` with `profile.get("_video_prompt", hold_base)`
   - Randomized age: `random.randint(18, 25)` replaces `25`
   - If `_video_prompt` not available, falls back to prompt_builder-style hardcoded base with randomized age

6. **Recipe created in Schema Engine**:
   - Created "video_recipe" schema with `tus` recipe containing 6 scenes (Hook, Problem, Discovery, Features, Transformation, CTA)
   - Each scene has name, prompt, duration, tts settings
   - Added `tts` config for voiceover
   - Deleted and recreated recipe once to fix "waiting for input" issue

### Files Modified (active path: /home/openhands/erp-stack/)
- `prompt-builder-service/gemini_client.py` — Added `_call_mistral_vision()`, updated system prompts for Thai ethnicity + packaging detail, `PRODUCT_ANALYSIS_SYSTEM` requires Thai ethnicity in output
- `prompt-builder-service/prompt_builder.py` — Sanitization logic for holding (usage verb replacement), cap-closed emphasis, packaging extraction filtering, final lips/skin removal pass
- `prompt-builder-service/prompt_templates.py` — STYLE_MAP "holding" has ethnic Thai descriptors + stronger "NOT applying" instruction
- `prompt-builder-service/persona_engine.py` — Added `clothing` and `hair_style` fields to all 6 personas (3 options each)

- `UGC_prompts/Holding_Product/master.prompt` — Holding instruction moved to beginning, before scene_description

### Key Architecture Decisions
