5. Added `width:100%` to `.page` — still didn't work

### Root Cause (Still Unidentified)
CSS Grid `min-width:auto` causes grid items to expand based on content width.
The clothing carousel items and country dropdown have intrinsic widths that exceed the grid column on mobile.
Adding `min-width:0` to `.row>*` should fix this but user reports it doesn't.
Possible causes:
- nginx caching old file (no-cache headers present but might not be sufficient)
- CSS specificity issue — another rule overriding min-width
- File on disk doesn't match what nginx serves
- Mobile viewport not triggering media query properly

### Current CSS in index.html (last known state)
```css
html,body{overflow-x:hidden}
.row{max-width:100%;overflow:hidden}
.row>*{min-width:0}
.page{width:100%;overflow-x:hidden}
.card{min-width:0}
@media(max-width:768px){.row{grid-template-columns:1fr}...}
```

async def scrape_tiktok_image(page, url):
    try:
        resp = await page.goto(url, timeout=25000, wait_until='domcontentloaded')
        if resp and resp.status == 403:
            return None
        await page.wait_for_timeout(4000)
        content = await page.content()
        if 'Security Check' in content or 'Verify' in content:
            return None
        image_url = await page.evaluate('''() => {
            const og = document.querySelector('meta[property="og:image"]');
            if (og && og.content && og.content.startsWith('http')) return og.content;
            const imgs = document.querySelectorAll('img');
            for (const img of imgs) {
                const src = img.src || img.getAttribute('data-src');
                if (src && src.startsWith('http') && 
                    (img.naturalWidth > 200 || img.width > 200) &&
                    !src.includes('avatar') && !src.includes('icon') && !src.includes('logo')) {
                    return src;
                }
            }
            return null;
        }''')
        return image_url
    except Exception as e:
        print(f"    Error: {e}")
        return None


async def download_image(page, url, save_path):
    try:
        resp = await page.request.get(url, timeout=15000)
        if resp.ok:
            body = await resp.body()
            if len(body) > 2000:
                with open(save_path, 'wb') as f:
                    f.write(body)
                return True
    except:
        pass
    return False

```
load_ugc_templates("holding") expects folder "UGC_holding"
Actual folder: "Holding_Product"
→ Returns empty dict for system/master/user.template/negative
→ templates["master"] = "" → falls back to STYLE_MAP
```

All 3 broken styles are affected:
- `Holding_Product/` → `load_ugc_templates("holding")` → ❌ folder not found
- `Product_Usage/` → `load_ugc_templates("usage")` → ❌ folder not found
- `UGC_Review/` → `load_ugc_templates("review")` → ❌ folder not found

**Problem 2: STYLE_MAP configs are actually correct**
- holding: "Model holding product gently in both hands..." ✅
- usage: "applying product to skin/face in real-time..." ✅
- review: "talking to camera, holding product..." ✅

No "NO hands, NO people" in STYLE_MAP. The master.prompt files (with conflicts) are never loaded.

**Problem 3: The ACTUAL conflicting prompts are in `modules/video/prompts/UGC_prompts/`**
These are used by `modules/video/prompt_builder.py` (different from prompt-builder-service):
- `Holding_Product/master.prompt` — "NO hands, NO people, NO product" conflicts with system.prompt "face reference"
- `Product_Usage/master.prompt` — same conflict
- `UGC_Review/master.prompt` — "NO hands, NO people" conflicts with user.template "real person reviewing"

### Prompt Flow (Two Paths)
```
Path A: tiktok-ugc-studio → prompt-builder-service → builds prompts → sends to video-gen
  → Uses STYLE_MAP (correct) + Gemini media prompts
  → UGC template files NOT loaded (folder mismatch)

Path B: modules/video/pipeline_affiliate.py → build_video_prompts() → Wan 2.7
  → Uses recipe scene_actions_by_category
  → Gemini product_profile["usage_action"] drives prompt
```

2. Wan 2.7 img2vid uses wrong first frame → distorted output
3. Gemini media generation may produce conflicting prompts for certain product types
