## BGM ซ้ำ (BGM repetitiveness)
### Problem
`bgm_style` was hardcoded as `"chill_loft"` in:
- `modules/video/main.py` line: `run_pipeline(bgm_style="chill_loft", ...)`
- This meant EVERY video got the same BGM

### Fix
- **modules/video/main.py**: Changed to randomly pick from all available BGM styles: chill_loft, luxury_jazz, upbeat_pop, energetic_edm, informative_jazz, asmr
- Used `random.choice(BGM_STYLES)` with a weighting system: chill_loft (20%), luxury_jazz (20%), upbeat_pop (25%), energetic_edm (15%), informative_jazz (15%), asmr (5%)
- Added `bgm_style` field to `VideoRequest` model so frontend can pass it (if not provided, random falls back)
- Pipeline DB in TUS also stores bgm_style per job now

## นางแบบไม่หลากหลาย (Model appearance repetitiveness)
### Problem
- `image_description` in profile was either Gemini output or generic fallback "Thai woman, 25-35 years old, pretty face"
- `build_video_prompt()` used generic "Thai woman 25" every time
- All 8 old videos had same-looking model

### Solution: Model Casting System
Created `/home/openhands/erp-stack/prompt-builder-service/model_casting.py`:
- 8 distinct "casts" (Thai model appearances):
  1. clean_girl (22, white tee, clean girl aesthetic)
  2. korean_trendy (23, oversized sweater, Korean street fashion)
  3. chic_minimal (25, neutral blouse, minimal chic)
  4. casual_cool (21, denim jacket, street style)
  5. soft_romantic (22, pastel lace dress, romantic)
  6. fashion_forward (24, cream blazer, modern chic)
  7. sporty_fresh (23, sporty outfit, athleisure)
  8. campus_babe (20, polo+skirt, campus fresh)
- Weighted random selection by category (beauty, fashion, food, etc.)
- Integrated into `build_image_prompt()` and `build_video_prompt()` via profile injection
- Gemini analysis output is STILL used for category/packaging_action/setting — only model visual appearance is overridden

### Pipeline Integration
- `profile["_model_cast"] = select_model_cast(...)` inserted after image analysis
- `build_image_prompt()` reads `profile["_model_cast"]["image_description"]` as scene_desc
- `build_video_prompt()` reads `profile["_model_cast"]["model_age"]` instead of hardcoded 25

### Key file modified
- `/home/openhands/erp-stack/modules/video/main.py` — BGM randomization + bgm_style in API
- `/home/openhands/erp-stack/prompt-builder-service/model_casting.py` — NEW model casting module
- `/home/openhands/erp-stack/prompt-builder-service/prompt_builder.py` — integrate model casting into build_image_prompt() + build_video_prompt()

## Re-compose script
Script was written to a temporary file and run via exec. It:
1. Read raw video + TTS paths from pipeline_logs.db
2. FFprobe'd durations
3. Calculated delay = (video_duration - voice_duration) / 2
4. Ran FFmpeg compose with delay + no -shortest
5. Copied to storage/videos/final_*.mp4

## Critical Lessons
- **moov atom position matters for web streaming**: Without `-movflags +faststart`, browser playback is broken (plays 4-5s then freezes)
- **Service Worker may still serve old cached final_*.mp4**: Hard refresh (Ctrl+Shift+R) needed
- **model_casting.py should NOT modify gemini profile for category/packaging**: Only override visual appearance

## Session 06:31 UTC — TUS Pipeline Fixes
### Committed: `59daecc` — "fix: resolve TUS pipeline status desync, stuck jobs, manual URL entry, toast position"

#### 1. 🔴 Stuck "running" jobs cleanup (40+ jobs)
- **Root cause**: `update_step()` in `pipeline_db.py` only checked for `("success", "error")` as terminal statuses — "skipped" was excluded → any job with a skipped step stayed "running" forever
- **Fix**: Added "skipped" to `TERMINAL_STATUSES = {"success", "error", "skipped"}`
- **Cleanup**: Ran script on all 40 stuck jobs (28 auto-completed as all steps were done, 12 marked failed with stale_processing/empty steps)

#### 2. 🔴 Two-DB pipeline status desync
- **Same root cause** as above — the `update_step()` all_done check didn't include skipped, so even successful jobs with skipped TTS stayed "running"
- Now properly syncs: all steps terminal → status="completed"

#### 3. 🔴 Manual Studio URL entry broken
- **Problem**: `/ugc/scripts/generate` and `/video/generate` ignored `product_url` entirely. When user entered only URL (no title), product_name was empty → script gen produced garbage
- **Fix**: Both endpoints now parse URL path to extract product name (Shopee/Lazada URL compatible). Uses `urllib.parse` to extract last path segment, decode URL encoding, replace hyphens/underscores with spaces
- Also fixed prompt-builder call in `/video/generate` to use extracted name

#### 4. 🟡 Toast position + partial result return
- **Toast position**: Moved from `bottom: 24px; right: 24px` (overlapped UI) to bottom-center (`left: 50%; transform: translateX(-50%)`). Z-index 100 still above modal (50)
- **Error duration**: Errors now show 5s (was 3s) for readability
- **Partial results**: `autoGenerateAll()` now tracks completed steps in `partialResults[]` and shows what succeeded on failure (e.g. "Image gen failed (สำเร็จ: สคริปต์, รูปภาพ)")
