## Session 2: Lip-Sync Deep Dive (02:27 - 03:44 UTC)

### Key Discovery: Gemini TTS → Prodia Lip-Sync
**Proper flow:**
```
Gemini TTS → raw PCM 24kHz → ffmpeg: atempo=1.25 + ar=16000 + ac=1 → WAV 16kHz mono
→ prodia_client.py: multipart {input image, audio: audio.wav, job.json with config.audio="audio.wav"}
→ POST /v2/job/async → Wan 2.7 lip-sync output (video + baked audio)
→ skip voiceover merge (Prodia output already has lip-sync audio)
```

### Fixes Applied (commits 02:27 - 03:35):

1. **prodia_client.py** (`046631d`):
   - `config["audio"] = "audio.wav"` in job payload
   - Multipart field name `"audio"` (not `"input"`)
   - Multipart order: image → audio → job.json (audio before job payload)
   - Antigravity confirmed: Prodia Wan 2.7 needs `config.audio` key + `"audio"` field

2. **pipeline_affiliate.py Step 7** (`7a26aa5`):
   - ffmpeg: `atempo=1.25 -ar 16000 -ac 1` → 16kHz mono WAV for Prodia
