## Dashboard Preset/Style Widget — Frontend Debugging Saga (14:30-15:14 UTC)

### User's complaint
"UGC หายเกลี้ยงเลย เหลืออันเดียว" → "Recipe, UGC icon งามๆ หายหมดเลย" → Both systems rendering empty.

### Root Cause: 5 layered bugs

**Bug #1: Nginx rewrite — `CONFIG_API` path mismatch**
- Running nginx config (`nginx -T`) has `location ^~ /api/tiktok/` which rewrites `/api/tiktok/(.*)` → `/$1` → port 8105
- I changed `CONFIG_API` from `/api/tiktok/pipeline/config` → `/api/pipeline/config` (drawn from file-based config which had fragmented location blocks)
- But running config uses GENERIC `/api/tiktok/` → my change broke the path! `/api/pipeline/config` no longer matches `/api/tiktok/`
- **FIX**: Reverted `CONFIG_API` back to `/api/tiktok/pipeline/config`

**Bug #2: `initDashboard()` never called for Studio tab**
- `switchTab()` only called `initDashboard()` for 'dashboard' tab
- When user clicked 'Studio' (content) tab → `initDashboard()` never ran → `#styleModalGrid` stayed "Loading..."
- **FIX**: Added `initDashboard()` + `loadRecipes()` to `switchTab('content')`

**Bug #3: Race condition — `_dashboardInitDone=true` before API call**
- `initDashboard()` set `_dashboardInitDone = true` BEFORE `await loadDashboardConfig()`
- If API call failed (network timing on page load) → no retry → `_dashboardConfig` = null forever
- **FIX**: Reset `_dashboardInitDone = false` on failure; check `_dashboardConfig.ok` before short-circuit

**Bug #4: `loadRecipes()` overwriting `renderPresetPicker()`**
- Two systems competing for `#recipePicker` element:
  - Old: `loadRecipes()` → fills with 8 recipe cards from `/pipeline/recipes`
  - New: `renderPresetPicker()` → fills with 12 presets from API config
- `loadRecipes()` ran AFTER `renderPresetPicker()` → overwrote presets with recipes
- **FIX**: `loadRecipes()` defers to `renderPresetPicker()` when `_dashboardConfig` is loaded; `renderPresetPicker()` renders AFTER loadRecipes in switchTab flow

**Bug #5: initDashboard force-render needed on Studio tab**
- On initial load, `initDashboard()` runs with dashboard tab visible (content tab hidden)
- DOM elements get populated but invisible
- When user opens Studio tab, need to re-render because elements may have been cleared/changed
- **FIX**: Added `initDashboard(true)` — forceRender param bypasses `_dashboardConfig.ok` cache check

### Final Architecture
```
DOMContentLoaded:
```
